# M6 网页后台（讲评投屏 + 下载打印）设计

日期：2026-10-23
状态：待产品负责人确认
上游：`docs/specs/2026-10-20-ai-mistake-book-design.md`（扫码登录方案、网页后台定位）；`docs/specs/2026-10-22-m4-analytics-design.md`（学情、题目详情、PDF 导出）；`docs/specs/2026-10-22-m5-practice-design.md`（练习卷）

## 1. 为什么做

手机上已经能拍卷、批改、看学情、导出 PDF。网页后台不重复这些，只做**手机上做着别扭的两件事**：

1. **上课讲评投到大屏**：第二天上课，老师在教室电脑上打开网页，把「这道题全班错了多少、错成什么样、学生原图」投到大屏，一道道讲。
2. **在办公室电脑上下载打印**：讲评单、错题单、练习卷要打印，学校打印机连的是电脑；从手机把 PDF 传到电脑很麻烦。

反目标沿用全项目的：**复杂、不方便使用**。网页上只看、只下载，不做第二套操作入口。

成功的样子：老师在教室电脑上打开网址，用小程序扫一下就登录；两三下点到这次作业，看到每道题的错误率格子，点开最红的那道，投影上是大字的错误人数、错答分组和学生原图，用「下一题」往下讲；课后在办公室电脑上点「下载讲评单」直接打印。

## 2. 目标

### 2.1 扫码登录

- 网页登录页显示一个**小程序码**和一句「用微信扫一扫，在小程序里确认登录」。
- 老师用微信扫码 → 打开小程序新增的「确认登录网页版」页 → 点「确认登录」→ 网页自动进入。小程序里可以点「取消」。
- 码 5 分钟过期；过期后网页显示「二维码已过期，点击刷新」。
- **配对数字**：网页二维码旁显示一个 4 位数字；小程序确认页显示同一个数字，并提示「请核对电脑屏幕上的数字一致后再确认」。防止别人把自己电脑上的码拿给老师扫、骗走登录。
- 登录后网页记住登录状态 **7 天**（产品负责人决定：与小程序一致，接受教室公用电脑上忘记退出的风险）；右上角可以「退出登录」（清掉浏览器里保存的登录状态）。
- 扫码的老师和小程序里是同一个账号，看到的是同一份数据。

### 2.2 选作业

- 登录后：左侧（或顶部）是自己的班级列表，选班级后列出这个班的作业（标题、学科、日期），点作业进入总览。
- 只显示自己的班级和作业，权限沿用现有归属校验（他人数据 404）。

### 2.3 作业总览（老师自己看，也可以投）

- 顶部：班级 · 学科 · 作业名 · 日期；全班人数、平均分、及格率、还有几项待复核（有待复核时提示「还有 N 项没复核，统计可能变化，请在手机上复核」）。
- 主体：**每道题一个格子**，显示题号和错误率；错得越多颜色越深（暖色纸张风格的红/橙）。主观题格子同样按错误率（没拿满分的人数占比）着色，加「主观」小标（我的判断：现有统计没有主观题得分率，统一用错误率最直观）。
- 点格子进入该题的投影页。
- 一个「下载打印」入口，进入单独的下载页（见 2.5）。总览页本身不放下载按钮，上课投屏时不会误点开带学生姓名的 PDF。

### 2.4 题目投影页（投到大屏的画面）

- 大字：「第 N 题　错了 X 人（Y%）」+ 进度条；正确答案；知识点。
- **错答分组**（客观题）：每组「写成 xxx，N 人」，旁边是该组学生作答的原图截图（裁剪图），点开放大全屏；组内图多时只先显示几张，可展开。
- 每组下面显示 **AI 推测原因**（复用 M4 的错因接口；还没生成时自动请求，失败就不显示，不报错）。
- 主观题：显示得分分布（满分 / 一半及以上 / 一半以下）和错答原图，不分组。
- **不显示任何学生姓名**（投影时避免学生在全班面前难堪）。
- 「上一题 / 下一题」按钮，键盘左右方向键同样可用；「全屏」按钮（浏览器全屏）；「返回总览」。
- 排版按**教室投影仪**设计：1024×768 也能看清，字大、对比强，不需要滚动就能看到错误人数和前两组。

### 2.5 下载打印

单独的「下载打印」页（从作业总览进入），点了直接下载 PDF（浏览器下载，不在页面里打开，文件名沿用现有导出的文件名）：

- **讲评单**（M4 `lecture`）
- **全班错题单**（M4 `class_students`，每个学生一份）
- **练习卷**（M5 `practice`）：可选「附答案 / 不附答案」。只下载已经在手机上生成好的练习卷；还没生成时按钮旁提示「练习卷请先在手机上生成」，网页上不出新卷子。

署名沿用老师在小程序里设置的名字；如果还没设过，网页上第一次下载时弹框让老师填一次（写回同一个账号）。

## 3. 不做（这次）

- 网页上拍照、上传、建班、建作业、改分、复核、生成或换练习题——都在手机上做。
- 批量复核（原计划 M6 内容，产品负责人决定往后放）。
- 单个学生页面、学生历史、个人错题单单独下载（全班错题单里已有每个人）。
- 学校/年级管理员视角、多老师协作。
- 数据大屏的图表动画、PPT 导出。
- 手机浏览器适配（网页只保证电脑和投影仪上好用）。

## 4. 绝不能出现的情况

- 投影页上出现学生姓名。
- 老师 A 扫码登录后看到老师 B 的任何数据。
- 别人拿到一个过期或已用过的二维码/登录凭证还能登录；二维码被确认后，登录凭证只能被那一个网页取走一次。
- 网页上的操作改动了批改结果（网页只读，除了「署名」和练习卷/讲评单导出这种本来就会生成文件的操作）。
- 在投影仪分辨率下看不清错误人数或需要滚动才能看到。

## 5. 约束

- **前端**：React + TypeScript（M3 时已改定 React，与小程序一致），Vite 构建，新目录 `web/`。配色沿用小程序「温暖纸本」主题变量。
- **后端**：沿用现有 FastAPI，不另起服务；新增扫码登录接口，其余全部复用现有接口（班级、作业、学情、题目详情、错因、导出、练习卷查询、`/me`）。
- **部署**：同一台服务器、同一个 nginx。网页静态文件由 nginx 提供，`/api/` 转给后端，所以网页和接口同源（签名图片链接 `/api/files/...` 直接可用，不需要跨域）。地址暂时是 `http://42.194.206.186`（还没有备案域名；产品负责人决定域名最后做）。有域名后切 HTTPS 不需要改网页代码。
- **小程序码**：用微信 `wxacode.getUnlimited` 生成（不限数量），`scene` 里放一次性票据，`page` 指向小程序新增的确认页。需要服务器上已有的 `WX_APPID` / `WX_SECRET`。现在小程序还只有体验版：生成码时用体验版（`env_version=trial`），做成配置项，正式发布后改成 `release`。只有体验成员能打开体验版的码——现阶段可以接受。
- **小程序改动**：新增一个确认页，需要重新上传一次体验版（用 `--mode staging` 构建）。
- 小程序新代码沿用 rpx 写法。

## 6. 已定（我的判断，产品负责人可推翻）

- **扫码登录流程**（按总设计第 216 行）：
  - 网页请求创建票据 → 后端生成随机票据（存 Redis，5 分钟过期，状态「待扫码」）并返回小程序码图片；
  - 小程序确认页拿到票据（从 `scene` 读），用老师自己的登录状态调用「确认」→ 票据变成「已确认」并绑定该老师；
  - 创建票据时另给网页一个**不放进二维码**的轮询密钥；只有带着这个密钥才能查询状态、取走凭证（别人拍到二维码也取不走登录）；
  - 票据里存 4 位配对数字；确认页打开时从后端取到这个数字显示给老师；
  - 网页每 2 秒轮询票据状态，看到「已确认」时拿到登录凭证（与小程序同样的 JWT，7 天，复用现有签发逻辑），票据随即删除，只能取一次；
  - 小程序扫码打开确认页时先标记「已扫码」，网页显示「已扫码，请在手机上确认」。
  - 微信接口调用凭证（access_token）在 Redis 缓存，过期前复用，不要每次登录都去换。
  - 创建票据要限流（按 IP，例如每分钟 10 次），避免被刷小程序码接口。
- **登录状态**：网页把 JWT 放在浏览器本地存储；接口 401 时回到登录页。「退出登录」只清本地，不做服务器端作废（凭证是无状态的；产品负责人接受 7 天有效）。
- **下载放单独页面**：不和投屏的总览页放在一起。
- **投影页不显示姓名**：只在网页上不渲染；接口照旧返回（老师自己的数据），不为此改接口。
- **错因**：复用 M4 的错因接口；网页打开题目页时请求一次，结果有缓存时不重复花钱（沿用 M4 的缓存逻辑）。
- **练习卷**：只能下载已有的；网页不触发生成。
- **待复核提示**：只提示数量，引导去手机复核，不在网页复核。
- **网页构建与上传**：部署时在开发机上构建 `web/` 并随代码一起上传，服务器上不装 Node（服务器只有 2G 内存）。`deploy.ps1` 相应扩展。
- **本地开发**：Vite 开发服务器把 `/api` 代理到本机后端。本地无法生成能用的小程序码时，提供**仅开发环境**可用的登录方式（例如后端 `DEBUG` 开关下的开发者登录接口，生产环境不注册该路由），方便本机调试页面。

## 7. 留给实现者

- 页面路由、组件拆分、状态管理（够用即可，不引入大型框架）。
- 小程序码图片是直接返回 PNG（base64）还是另给一个图片地址。
- 错答分组与原图的对应方式（题目详情接口里分组带学生提交 id，原图也带提交 id，可在前端对应）。
- 投影页大图放大的交互细节、组内图片显示几张。
- 票据状态的具体字段与接口命名。
- 测试：后端扫码登录接口按现有 pytest 风格测；网页用 Vitest 测关键逻辑（轮询、401 处理、分组与原图对应、不渲染姓名）。

## 8. 验收要点

- 电脑浏览器打开 `http://42.194.206.186`，看到小程序码和 4 位数字；体验成员用微信扫码 → 小程序确认页显示同样的数字 → 点确认 → 网页 3 秒内进入。
- 不带轮询密钥查询票据拿不到凭证。
- 码 5 分钟后过期，网页提示刷新；确认后的票据第二次取凭证失败。
- 老师 B 登录看不到老师 A 的班级；直接拼 A 的作业地址得到「找不到」。
- 作业总览：每题错误率格子颜色正确，与小程序学情页数字一致。
- 题目投影页：错答分组人数与小程序一致；原图能显示、能放大；**页面上没有任何学生姓名**；左右方向键翻题；1024×768 下不用滚动能看到错误人数和前两组。
- 下载讲评单、全班错题单、练习卷（附/不附答案）都能在电脑上打开，中文和署名正常；练习卷还没生成时有提示。
- 网页上没有任何改分、复核、拍照入口。
