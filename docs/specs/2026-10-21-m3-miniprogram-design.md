## 1. 为什么做、做成什么样

M1 后端已经能用接口走通"拍卷 → AI 批改 → 老师复核"，但老师没有可用的界面。M3 做一个**老师端微信小程序的最小可用版**，让第一批老师尽快用起来，配合 M7 部署后以个人主体体验版发布试用。

**老师的一次完整使用（已与产品负责人确认）**

1. 微信一键登录，不填任何资料。
2. 建班：填班名、选年级、粘贴名单（一行一人，可带学号）。
3. 建作业：选学科（默认上次）、写标题；可拍一张答案卷让 AI 提取答案，老师确认/修改；也可跳过。
4. 连拍全班卷子，每张拍完自动上传；拍完即可离开。
5. 之后回到作业看进度（如"已批 40/42"），看不清的卷子标红提示重拍。
6. 复核：只看 AI 拿不准的题，每题有错题截图、学生答案、正确答案，可判对/判错/改分；认错学生的卷子可以换成正确学生。
7. 看结果：每个学生一行显示总分，点进去看每道题和错题。

## 2. 目标、非目标、反目标

**目标**
- 老师从首次打开到拍完第一份卷子 ≤ 2 分钟（含建班）。
- 第一版覆盖小学和初中（1–9 年级）全部学科的作业；不依赖知识点数据。
- 上面 7 步全部能在手机上完成，不需要电脑。

**非目标（第一版不做）**
- 班级学情统计、错题本 PDF、举一反三（M4/M5）。
- 网页后台（M6）。
- 微信订阅消息通知（第二版再做，老师自己打开看进度）。
- 拍名单照片识别（只支持粘贴文本）。
- 题目知识点展示（数据由 M2 并行准备，题目知识点暂为空）。
- 学生端、家长端。

**反目标（即使功能都能用，出现这些也算失败）**
- **复杂、不方便使用**（产品负责人原话）。具体约束：
  - 任何页面的主要操作一眼可见，不需要说明书。
  - 不出现非必要的表单字段和设置项；能给默认值的都给默认值。
  - 首页到"开始拍卷"不超过 3 次点击（已有班级时：选作业或新建作业 → 开始拍）。
  - 错误提示用老师能懂的话说明"发生了什么、该怎么做"，不出现技术术语和错误码。
  - 等待时不让老师盯着屏幕；能离开的地方明确告诉老师"可以离开"。

## 4. 页面

| # | 页面 | 内容 | 主要操作 |
|---|------|------|----------|
| P1 | 首页（班级列表） | 每个班一张卡片：班名、人数、最近一份作业及其状态（"6 题待复核"/"批改中 40/42"/"全部完成"） | 点班级进入 P2；"新建班级" |
| P2 | 班级详情 | 作业列表（新的在前），每项显示进度摘要；右上角"名单" | "新建作业"；点作业进入 P4 |
| P3 | 新建班级 / 名单 | 班名、年级（1–9 选择器）、名单粘贴框；显示解析出的人数预览 | 保存；之后可追加名单 |
| P4 | 作业主页 | 顶部：学科、标题、答案卷状态；中部进度条和页面列表（每张卷子：学生名或"未识别"、状态、失败原因）；底部按钮 | "拍答案卷"、"开始拍卷"、"去复核 N 题"、"看成绩" |
| P5 | 拍照页（答案卷与学生卷共用） | 全屏取景框 + 快门；底部缩略图条显示已拍张数与每张上传状态 | 连续按快门；"从相册选"；"完成" |
| P6 | 答案卷确认 | AI 提取的每题：题号、答案、分值（可空） | 修改、删除行、加行；"确认答案" |
| P7 | 复核 | 一次一题卡片：错题截图、学生名（或"未识别学生"）、题目、学生答案、正确答案、AI 判定与分数、原因标签 | "判对"、"判错"、"改分"、"换学生"（打开该班名单选择）；自动进入下一题 |
| P8 | 成绩 | 学生列表：姓名、总分、待复核数；点进去看该生每道题（对错、得分、错题截图） | 无编辑（改分在复核页做） |
| — | 新建作业 | 底部弹层：学科（默认上次）、标题（默认"MM-DD 作业"） | 创建后直接进入 P4 |

第一次进入且没有班级时，P1 显示引导"先建一个班"，只有一个按钮。

界面风格：简洁、白底、大字号、大按钮；状态颜色只用三种（处理中灰、需要注意黄、出错红、完成绿可选）；不做复杂动画。具体视觉由实现者按上述约束决定。

## 5. 关键行为

**登录**：`Taro.login` 取 code → `POST /api/auth/wx-login` → 保存 token（本地存储）。任何接口返回 401 时静默重新登录一次再重试；仍失败则提示"登录已过期，请重新打开小程序"。

**拍卷与上传**
- 拍照页使用小程序 `camera` 组件做连拍（不每张都弹系统相机）；同时提供"从相册选"（一次最多 20 张）给已经用系统相机拍好的老师。
- 上传前压缩：长边约 2000px、JPEG（保证远小于后端 10 MB 上限）。
- **按拍摄顺序逐张上传**（后端靠上传顺序把无姓名的续页归到前一页的学生；并行上传会打乱顺序）。上传队列在拍照页后台进行，老师可以一直按快门。
- 单张失败自动重试 2 次；仍失败的在缩略图上标红，可点"重传"。
- 后端返回 `duplicate: true` 时视为成功（同一张已经传过）。
- 后端返回 429（本月额度用完）时停止队列，提示"本月批改额度已用完"，已传的不受影响。
- 后端返回 503（批改队列暂不可用）时：页面已保存，提示"已收到，稍后会自动开始批改"，并在稍后重传同一张以重新排队。
- 老师在上传未完成时离开拍照页：提示"还有 N 张没传完，离开会中断"，可选继续上传或放弃剩余。第一版不做后台持续上传。

**进度与刷新**
- P4 打开时每 3 秒轮询 `GET /api/assignments/{id}/progress` 与 `/pages`，全部页面结束（done/failed）后停止轮询；离开页面停止。
- 失败原因转成老师语言：`unreadable` →"看不清，请重拍这张"；`model_output_invalid` →"这张没批出来，请重拍"；`model_unavailable`/`internal_error` →"批改服务暂时出错，点重试"（重试 = 重新上传同一张照片，后端会重新排队）。

**复核**
- 数据来自 `GET /api/assignments/{id}/review`；判对/判错/改分调用 `PATCH /api/question-results/{id}`；换学生调用 `PATCH /api/pages/{page_id}`（候选为本班名单）。
- "未识别学生"的页面（`pages_unassigned`）排在最前面，先让老师选学生，再看题。
- 每次操作成功后自动进入下一项；全部处理完显示"复核完成"并回到 P4。

**没有答案卷时（产品负责人 2026-10-21 选定方案 B，修改了总体设计第 7.3 节）**
- "答案未校验"本身不再让题目进入复核；只有 AI 自己拿不准（置信度低于阈值）或学生没认出来的题才进复核。
- 同一份作业里，同一题号的"正确答案"以全班 AI 自解结果的多数为准；某张卷子上 AI 给出的正确答案与多数不一致时，这道题进入复核（原因"答案不一致"）。
- P4 和成绩页标注"本次没有答案卷，答案由 AI 判断"；新建作业后的 P4 上"拍答案卷"作为第一个按钮突出显示，但不强制。
- 风险（已告知并接受）：AI 把某道题解错时，全班这道题都会判错，直到老师发现并改正。

**重拍与重试（我的决定）**
- `unreadable` / `model_output_invalid` 的卷子：在 P4 点"重拍" → 进入拍照页拍一张 → 调用新接口**替换这张卷子**（保持原来的上传顺序，状态回到排队），红色提示随之消失。
- `model_unavailable` / `internal_error` 的卷子：点"重试" → 调用新接口让后端直接重新排队，不需要重新上传图片，客户端不必保留本地文件。
- 进度显示：P4 同时显示"已批 x/y 张"（来自 `/progress`）和"已出成绩 m/n 人"（`/submissions` 数量 / 名单人数）；P1 卡片只显示张数和待复核数。

**名单修改（我的决定）**：P3 名单里每个学生可以改名、改学号；没有成绩的学生可以删除，已有成绩的学生只能改名。

**学科选项（我的决定）**：中文名称显示。1–6 年级班级：语文、数学、英语、科学、道德与法治、其他；7–9 年级再加物理、化学、生物、历史、地理（"道德与法治"对应后端 `politics`）。

**照片尺寸（我的决定）**：上传前用 canvas 把长边缩到 2000px 以内再压成 JPEG，不只是降低质量。

**答案卷**
- 拍一张或从相册选一张 → `POST /api/assignments/{id}/answer-key`（同步，等待约 10–30 秒，显示"正在识别答案…"）→ P6 确认 → `PUT`。
- 已有学生卷批完后再确认答案卷时（`regrade_suggested: true`），提示"已批的卷子不会自动重批"。第一版不做重批。

## 6. 用到的后端接口（M1 已有）

| 用途 | 接口 |
|------|------|
| 登录 / 我的信息 | `POST /api/auth/wx-login`，`GET/PATCH /api/me` |
| 班级 | `GET/POST /api/classes`，`DELETE /api/classes/{id}` |
| 名单 | `GET /api/classes/{id}/students`，`POST /api/classes/{id}/students:import` |
| 作业 | `GET /api/classes/{id}/assignments`，`POST /api/assignments`，`GET /api/assignments/{id}` |
| 答案卷 | `POST/PUT/GET /api/assignments/{id}/answer-key` |
| 上传 | `POST /api/assignments/{id}/pages`（multipart `file`） |
| 进度 / 页面 / 成绩 | `GET /api/assignments/{id}/progress`、`/pages`、`/submissions`，`GET /api/submissions/{id}` |
| 复核 | `GET /api/assignments/{id}/review`，`PATCH /api/pages/{id}`，`PATCH /api/question-results/{id}` |
| 图片 | 后端返回的签名 URL（`image_url`、`crop_url`），有效期 10 分钟，过期后重新拉取列表 |

P1 卡片上的"最近作业状态"需要对每个班取最近一份作业的进度；第一版用现有接口逐个请求（班级数量少），不新增聚合接口。

**M3 需要的后端改动（随 M3 一起做，均需测试；老师只能操作自己的数据，他人资源返回 404）**

| 改动 | 说明 |
|------|------|
| `POST /api/pages/{id}:replace`（multipart `file`） | 仅限 failed 页面：换上新图片（同样的类型/大小/去重/额度检查），保留 seq，清空旧结果，状态回到 queued 并排队 |
| `POST /api/pages/{id}:retry` | 仅限 failed 且原因为 `model_unavailable`/`internal_error`：重新排队（沿用现有 retry_count 生成新任务号），不改图片 |
| `PATCH /api/students/{id}`、`DELETE /api/students/{id}` | 改名/改学号；删除仅限没有任何成绩和页面关联的学生（否则 409"已有成绩的学生不能删除，可以改名"） |
| 复核规则（方案 B） | `needs_review` 去掉"答案未校验"条件；新增"无答案卷时，同题号正确答案与全班多数不一致 → 复核，原因 `answer_mismatch`"。多数在每张卷子写入时用已完成卷子重新计算；之前卷子因此新变成不一致/一致的题同步更新 |

## 7. 开发与运行环境

- 本地开发：后端在本机 `uvicorn` 运行；微信开发者工具中勾选"不校验合法域名"；小程序的接口基地址通过 Taro 环境变量配置（开发 / 体验版各一个）。
- 真机调试和体验版需要 HTTPS 且已备案的域名（属于 M7，不在 M3 内）。M3 完成标准用开发者工具和真机预览（局域网或调试模式）验证。
- 小程序 AppID 由产品负责人提供（个人主体）。没有 AppID 时可先用测试号开发。

## 8. 测试与验收

- 纯逻辑（上传队列的顺序与重试、错误码到中文提示的映射、轮询停止条件、名单预览解析）写单元测试（Vitest 或 Jest，由实现者选）。
- 页面层不强求自动化测试；验收按第 1 节 7 步在开发者工具里对接本地后端走一遍，后端模型用真实通义千问 key 或后端的 FakeModel。
- 验收清单：首次登录到拍完第一张 ≤ 2 分钟；连拍 10 张顺序正确；断网一张后能重传；429 / 503 提示正确；复核每种操作生效、成绩页分数随之变化；换学生后续页一起换。
