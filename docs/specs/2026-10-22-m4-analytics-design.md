# M4 学情与报告 + M2 知识点库 设计

日期：2026-10-22
状态：待产品负责人确认
上游：`docs/specs/2026-10-20-ai-mistake-book-design.md` 第 9、10 节；`docs/specs/2026-10-21-m3-miniprogram-design.md`

## 1. 为什么做

老师批完一次作业后，第二天上课要知道**全班错了哪些题、错在哪**，好决定先讲什么、怎么讲。平时不会逐个学生看，只有**某个学生错得特别多、特别离谱**时才点进去。讲评和订正常常要**打印**。

M3 已经能批改、复核、看每个学生的成绩；M4 在此之上回答「这次作业全班怎么样、明天讲什么」。M2 提供知识点库，让「薄弱知识点」有内容可归。

成功的样子：老师打开一次作业的学情页，十秒内知道明天先讲哪两道题、大部分学生错成了什么样；需要时一键导出讲评单或某个学生的错题单拿去打印。

## 2. 目标

### 2.1 班级学情页（按一次作业）

入口：作业页（P4）底部加「看学情」按钮，至少有 1 份成绩时出现。

页面自上而下：

1. **全班概况**：平均分、及格率、已出成绩人数 / 名单人数、待复核题数。
   - 及格：得分 ≥ 满分的 60%。满分 = 该学生各题 `max_score` 之和；某题 `max_score` 为空时按答案卷分值，再没有就不计入满分（该题也不计入得分率）。
   - 待复核数 > 0 时，概况下方显示提示「还有 N 题待复核，统计可能不准」并可点去复核。统计照常包含这些题的当前判定。
2. **错得最多的题**：按错误人数从多到少，列出所有至少错 1 人的题。每题显示题号、知识点名（有就显示）、错误人数、正确率（条形）、最常见错答。点进去到「题目详情」。
   - 同一题号在不同学生间视为同一道题（按 `question_no` 归并，和现有无答案卷的多数比较一致）。
3. **薄弱知识点**：本次作业中，按「该知识点下的错题人次」排序取前 3 个；每个显示名称和错题人次。没有任何题带知识点时整块隐藏。
4. **需要关注的学生**：见 2.3。

### 2.2 题目详情页

- 题目文字（取任一学生该题的 `question_text`）、正确答案（有答案卷用答案卷）。
- **错答分布**：把错的学生按「学生答案」归组。归组前做规范化（复用 `grading/consensus.normalize_answer`）；没写或没看清的归到「没写 / 没看清」。按人数从多到少，每组显示：错答原文（取组内出现最多的写法）、人数、学生名单。
- **AI 错因（每组一句）**：例如「把长加宽当成了面积」。打开页面时异步请求，先显示分布、错因稍后补上；同一题同一组只生成一次并存库，组的成员或答案变化后再生成。界面标注「AI 推测」。人数为 1 的组和「没写 / 没看清」不生成。
- **学生答题截图**：错的学生的裁剪图（现有 `crop_key`），点开大图。
- 从这里可以点学生名进入该学生页（2.3）。

### 2.3 需要关注的学生 与 学生页

- **挑选规则**：本次作业得分率 < 60%，或比全班平均得分率低 20 个百分点及以上；按得分率从低到高。没有符合的学生时整块隐藏。
- 每人显示姓名、分数 / 满分、错题数。
- **学生页**：沿用现有成绩详情页（P8 详情：每题对错、截图、学生答案、正确答案），顶部增加：
  - **最近几次作业**：同一班级、同一学科最近 5 次作业的分数和得分率（只列有成绩的），能看出是偶然还是一直跟不上；
  - **AI 总结**：两三句话，说这个学生本次（结合最近几次）哪类题、哪个知识点容易错。按需生成并存库，成绩变化后重新生成。标注「AI 推测」。
- 普通学生（不在关注名单里）从成绩列表进入时也能看到这些内容。

### 2.4 打印（导出 PDF）

两种打印件，A4 竖版，黑白打印清楚：

- **班级错题讲评单**（每次作业一份）：页眉（班级、作业标题、日期、署名）；全班概况；错得最多的题（默认前 10 题，每题：题目、正确答案、正确率、错答分布、最多 3 张典型截图）。
- **学生个人错题单**（每个学生每次作业一份）：页眉（学生姓名、班级、作业、日期、署名）；每道错题：截图、学生答案、正确答案、留白的「订正」区。全对的学生不提供。

流程：

- 入口：学情页右上「导出」→ 选「班级讲评单」；学生页「导出错题单」。另提供「全班错题单」：一次生成该作业所有有错题学生的个人错题单，合成一个 PDF（每人另起一页），方便一次打印发下去。
- **署名**：第一次导出时弹出输入框询问署名（如「王老师」），保存到 `teachers.display_name`；之后导出直接用，导出面板里显示当前署名并可修改。未设置署名时用「老师」。
- 服务器生成 PDF，存到存储里，返回带签名的临时链接；小程序 `downloadFile` 后 `openDocument`（允许右上角转发），老师转发到电脑微信去打印。
- 生成期间显示「正在生成…」；生成失败给中文提示，可重试。

### 2.5 M2 知识点库

- 范围：1～9 年级。学科与年级：语文 1–9、数学 1–9、英语 3–9、道德与法治 1–9、科学 1–6、物理 8–9、化学 9、生物 7–8、历史 7–9、地理 7–8。
- 依据义务教育各学科课程标准（2022 年版）的学段与内容领域组织：`学科 → 领域 → 主题 → 知识点`，不绑教材版本，沿用现有 YAML 格式（`data/knowledge/*.yaml`，叶子带 `grade_band`）。
- 粒度：叶子是一节课能讲清的知识点；每科每个年级大约 15～40 个叶子，太细会让模型乱归、太粗没法指导讲评。
- 由 Claude 依据课标生成，**未经教师审核**；文件头注明版本和「待试用反馈修订」。试用中老师觉得名字不对或归错，按反馈改 YAML 再导入。
- 导入：部署时执行现有导入脚本（`python -m app.knowledge.loader`），可重复执行；改名或删点不能破坏已关联的批改结果（导入按 `code` 更新，删除的点在结果里置空）。
- 批改流水线已有「按学科年级取候选知识点并让模型选」的逻辑，M2 导入后新批改的题自动带上知识点。

## 3. 不做（这次）

- 跨多次作业、按知识点整理的完整个人错题本（只做 2.3 的「最近 5 次分数」和 AI 总结）。
- 给已经批过的旧题补知识点。
- 举一反三 / 练习卷（M5）、网页后台（M6）、家长端。
- 教材版本与章节映射。
- 按班级跨作业的趋势图、年级对比。

## 4. 绝不能出现的情况

- 统计看起来确定但其实不准：有待复核时必须提示；AI 生成的错因和总结必须标「AI 推测」。
- 页面因为等 AI 而打不开：AI 内容一律异步、可失败，失败时那一行不显示，不影响统计。
- 一个学生的错题单里混进别的学生的题，或讲评单里出现名单外的名字。
- PDF 里中文缺字、截图糊成一团、黑白打印看不清。
- 老师 A 能拿到老师 B 的学情或 PDF（沿用现有按老师校验归属）。

## 5. 约束

- 服务器 2 核 2 GB（腾讯云轻量，Docker Compose）；PDF 生成不能吃掉大量内存，按请求生成，不做常驻渲染服务。
- 生产镜像里要有中文字体，PDF 才不会缺字。
- AI 调用用现有模型适配层（通义千问 `qwen3-vl-plus` 或同 provider 的文本模型），按需生成、结果存库复用；调用记入现有用量记录。
- 生成的 PDF 含学生姓名：存私有存储、签名链接短时有效；PDF 文件保留 7 天后清理（复用现有定时清理任务的思路）。
- 小程序界面沿用「温暖纸本风」的样式变量和组件。
- 所有新接口沿用现有鉴权和归属校验；统计只针对状态 done 且已归属学生的页。

## 6. 已定（我的判断，产品负责人可推翻）

- 学情按「一次作业」统计，不做跨作业汇总（和拍卷、复核的单位一致）。
- 及格线 60%、关注线「低于平均 20 个百分点」、讲评单默认前 10 题、最近 5 次作业：都是可配置常量，先用这些值。
- 错答归组用现有答案规范化函数，不让 AI 归组（可解释、稳定、无成本）；AI 只负责给组写一句错因。
- 「全班错题单」合成一个 PDF，而不是每人一个文件，方便一次打印。
- **什么算「错」**：没拿满分就算错（和 M3「改分：满分记对，非满分记错」一致，即 `is_correct=False`）。所有视图（每题错误人数与正确率、关注名单的错题数、薄弱知识点人次、个人错题单）都用这一个定义；部分得分的题在错答分布和错题单里显示「得 x / y 分」。「全对的学生不提供错题单」指没有任何失分题。
- **主观题**（`is_subjective`，作文、证明等）：不做错答归组，也不生成每组 AI 错因；题目详情改为显示得分分布（如「满分 12 人 / 3–4 分 9 人 / 0–2 分 5 人」）和失分学生的截图。在「错得最多的题」里照常按失分人数排序，「最常见错答」一栏不显示。
- **没批完的卷子不进统计，并明确提示**：统计只用已批完且已认出学生的页。排队中、批改中的页还没认出是谁的，没批成的页也认不出，所以没法判断「哪个学生还没批完」；改为只要作业里还有这类页或待选学生的页，概况下方就提示「还有 N 张卷子没批完或没认出学生，统计暂未包含」。（写计划时修订：原先按学生排除的做法实现不了。）
- **PDF 链接的权限**：导出接口按老师归属校验（老师 B 请求老师 A 的作业返回 404），返回的签名链接 10 分钟内有效；链接本身不再绑定老师（和现有图片链接同一机制）。验收里的「老师 B 被拒绝」指导出接口拒绝。
- **手机上验收 PDF 依赖域名**：小程序下载文件要求 HTTPS 和已备案域名，目前服务器只有 IP，域名备案由产品负责人稍后办理。M4 在开发者工具里关闭域名校验完成验收，手机上打开、转发 PDF 的验证放到域名和 HTTPS 就绪后（M7）。

## 7. 留给实现者

- PDF 生成方式（HTML 模板转 PDF 或直接排版库）与字体选择，满足第 5 节的内存和中文要求即可。
- 统计接口的拆分方式（一次返回整页，或概况与题目详情分开）、缓存策略。
- AI 错因 / 总结的提示词、存储表结构和失效判断的细节。
- 知识点 YAML 按学科拆成多少个文件。

## 8. 验收要点

- 用 M3 验收时生成的测试卷（张三 / 李四 / 王五 / 赵六等，已知每题对错）建一份作业：学情页的平均分、及格率、每题错误人数、错答分布与手算一致。
- 有待复核题时出现提示；复核后统计随之变化。
- 关注名单按规则挑出低分学生；学生页显示最近几次分数与 AI 总结（标「AI 推测」）。
- 两种 PDF 及「全班错题单」在开发者工具里能生成并打开（手机上打开、转发待域名就绪后验）；在电脑上 A4 打印，中文不缺字、截图清楚；首次导出询问署名，之后不再问，可修改。
- 有没批完或没认出学生的卷子时，概况提示张数，统计不含这些卷子；部分得分的题计为错并显示得分。
- 导入 M2 知识点后，新批改的数学题带上知识点，学情页显示薄弱知识点。
- 老师 B 请求老师 A 作业的学情或导出接口被拒绝。
